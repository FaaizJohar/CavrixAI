# Cavrix AI — Security Model

Cavrix AI has profound access to the host environment. The split architecture mandates strict security boundaries.

## 1. Central Permission Engine

The Desktop Agent routes every incoming action request through a `PermissionEngine`. This engine classifies every action into trust levels.

| Trust Level | Description | Example Actions |
|-------------|-------------|-----------------|
| **SAFE** | Read-only or non-destructive actions. Auto-approved. | `weather_report`, `system_monitor` |
| **LOW_RISK** | Local actions that alter state minimally. Auto-approved. | `open_app`, `youtube_video` |
| **CONFIRM** | Destructive or privacy-sensitive actions. Requires UI token. | `delete_file`, `send_message`, `shutdown` |
| **HIGH_RISK** | Deep system modifications. Requires UI token + re-auth. | `firewall_modification` |
| **DENY** | Actions explicitly blocked at the framework level. | `read_credentials`, `eval()` |

**CRITICAL:** The LLM cannot authorize `CONFIRM` actions by injecting `confirmed=True`. The confirmation token is a short-lived cryptographic nonce generated by the Web UI and validated by the Agent.

## 2. DevAgent Sandbox

Code generation and execution via `DevAgent` must not impact the host Cavrix process or random file locations.
- **Isolated Directory:** All operations occur within a dedicated, disposable workspace.
- **Path Traversal:** Strict `pathlib.Path.resolve()` checks ensure generated code cannot escape `../../` into the home directory.
- **Timeout/Resource Limits:** Generated scripts run with strict execution timeouts.

## 3. File System Boundaries

The `file_controller` operates on predefined zones:
- **NORMAL:** (`Desktop`, `Downloads`, `Documents`) - Standard operations permitted.
- **SENSITIVE:** (`Projects`, `AppData`) - Read operations require `CONFIRM`, write operations are logged heavily.
- **PRIVATE:** (`~/.ssh`, `.env`, browser profiles) - Explicitly blocked (`DENY`).
- **SYSTEM:** (`C:/Windows`) - Explicitly blocked (`DENY`).

## 4. Browser Isolation

Webpages, PDFs, and external transcripts read by Cavrix are treated as **UNTRUSTED DATA**. 
External data is passed to the LLM in a separate context block and can never override system instructions (Preventing Prompt Injection).

## 5. Network Security

- **Outbound Only:** The Desktop Agent never opens a listening port. It makes an outbound TLS connection to the Gateway.
- **Device Pairing:** Agents are paired using cryptographic keys. A compromised session token on the Web cannot issue commands to an offline or un-paired agent.
